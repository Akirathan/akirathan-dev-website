Below, I list few surprises for anybody coming from a high-level SW world like JavaScript:

### No dynamic memory allocation
C++'s `new` operator does not work.
More specifically, you can configure heap memory region in the linker script, but it was easier for me just not to do dynamic memory allocation.
There is no operating system that would allocate a new memory page for you.
There are even no virtual addressing instructions.
The available memory is "allocated" during build time via the linker script - you have a hardcoded addresses of everything that you can use.

### No parallelism
There is, obviously, no parallelism when you have just a single core.
But you can still somehow emulate asynchronous code by implementing handlers that will be called based on interrupts - for example when some internal clock ticks.

### Bit manipulation
Embedded programming, probably along with cryptography, is one of few fields where bit manipulation is very prevelant.
Any interaction with the device, like lighting up a diode, reading a buffer from a network card, or holding a higher voltage on some wire, is done by writing or reading certain bits to some addresses.
Usually, a decent embedded device manufacturer will publish source code that will do that for you, so you don't have to figure out which bit exactly you need to trigger.

### Real-time OS is not an OS
[Real-time OS] is not really an operating system.
It is just a scheduler of tasks implemented as a bunch of assembly.
