## Microcontrollers
Playing with a small STM32 microcontroller - a single core, a few KB of RAM and 256 KB of flash memory.
This was a nice low-level introduction to the SW world, where SW meets HW tightly.

Done as a bachelor thesis with the goal to develop a thermostat with configurable temperature in certain periods for the STM32 platform that is accessible through the internet.
GH repo: [Akirathan/STM32-smart-heating](https://github.com/Akirathan/STM32-smart-heating).
Later, I started a part-time job at [ComAp](/work/comap) based on this work.

Below, I list a few surprises for anybody coming from the high-level SW world like JavaScript:

### No dynamic memory allocation
C++'s `new` operator does not work.
More specifically, you can configure a heap memory region in the linker script, but it was easier for me just not to do dynamic memory allocation.
There is no operating system that would allocate a new memory page for you.
There are not even any virtual addressing instructions.
The available memory is "allocated" during build time via the linker script - you have hard-coded addresses of everything that you can use.

### No parallelism
There is, obviously, no parallelism when you have just a single core.
But you can still somehow emulate asynchronous code by implementing handlers that will be called based on interrupts - for example when some internal clock ticks.

### Bit manipulation
Embedded programming, probably along with cryptography, is one of the few fields where bit manipulation is very prevalent.
Any interaction with the device, like lighting up a diode, reading a buffer from a network card, or holding a higher voltage on some wire, is done by writing certain bits to some addresses or reading them from there.
Usually, a decent embedded device manufacturer will publish source code that will do that for you, so you don't have to figure out which bit exactly you need to trigger.

### Real-time OS is not an OS
[Real-time OS](https://en.wikipedia.org/wiki/Real-time_operating_system) is not really an operating system.
It is just a scheduler of tasks implemented as a bunch of C code and assembly.

Later on, this evolved into a [contribution](https://www.eclipse.org/lists//cdt-dev/msg32396.html) to Eclipse CDT - I have implemented a code generation feature there that generates code for virtual method overrides in C++.

## Kubernetes scheduler
Done as part of the *software project* - a team effort spanning an entire year.
The goal was edge cloud optimization - guarantee certain latencies between clients and the cloud, i.e., responses will not take longer than 50 ms for 90% of requests.
Achieved by monitoring the entire network, figuring out the optimal layout and possibly migrating some apps between nodes.
